# Requirements: Engineering Growth OS

**Defined:** 2026-04-13
**Core Value:** Every sprint leaves a knowledge artifact — so pattern gaps shrink, self-doubt reduces, and the next sprint is faster and more confident than the last.

- [x] **VAULT-01**: Obsidian vault folder structure created at `Personal/Cashea/` with numbered prefixes (00-inbox, 10-concepts, 20-tickets, 30-weekly, 40-resources, 50-mocs, 99-templates)
- [ ] **VAULT-02**: Core plugins installed and configured in order: Templater, Dataview, Tasks, Obsidian Git, Periodic Notes, Excalidraw, Omnisearch, Linter
- [x] **VAULT-03**: Vault git repo initialized as private GitHub repo (`cashea-knowledge-vault`), separate from cashea-backend, with 30-min auto-commit via Obsidian Git
- [ ] **VAULT-04**: 6 MOC (Map of Content) files created: MOC-Backend, MOC-Infra, MOC-System-Design, MOC-Cashea-Architecture, MOC-Observability, MOC-External-Services
- [ ] **VAULT-05**: Dataview queries built into MOC files (recent tickets, learning-gap concepts, unlinked concepts per domain)
- [ ] **VAULT-06**: Tag taxonomy configured and documented (type tags: #concept #ticket #weekly #resource #moc; domain tags: #backend #database #infra #system-design #observability #security #api #testing #devops #communication; status tags: #to-read #in-progress #reviewed #learning-gap #resolved)

### CAPT — Knowledge Capture

- [ ] **CAPT-01**: Concept article template created in Templater with all sections: What It Is, How It Works, How We Use It in cashea-backend, Related Concepts, Resources to Go Deeper, Things to Learn/Reinforce
- [ ] **CAPT-02**: Ticket reflection template created with sections: What Was Hard, What I Learned, Concepts Encountered, What I'd Do Differently (writable in under 2 minutes)
- [ ] **CAPT-03**: Ticket reflection is written before closing any branch or PR (rule: no merge without reflection)
- [ ] **CAPT-04**: New concept encountered in a ticket creates at minimum a stub (title + one-liner + wikilinks) before the session ends
- [ ] **CAPT-05**: Each concept article embeds 3-5 resources: 1 official doc + 1 deep resource + 1 quick mental model — no global reading list
- [ ] **CAPT-06**: `#learning-gap` tag applied to concept articles where knowledge feels weak; queried in weekly review to surface gaps

### REFL — Weekly Reflection

- [ ] **REFL-01**: Weekly review template created with: recent ticket summaries (Dataview), learning-gap concepts (Dataview), skill domain self-rating by trend, one mandatory capability assertion ("I can now X that I couldn't before"), one structural improvement nomination (deferred 8 weeks)
- [ ] **REFL-02**: Survival mode version documented before week one: 3-question review, one sentence per ticket, no new articles — exists as a standing template
- [ ] **REFL-03**: Dataview queries in weekly review auto-pull: tickets closed this week, concepts tagged #learning-gap, resources tagged #to-read
- [ ] **REFL-04**: Weekly reflection happens every week — hard weeks use survival mode, not skipped

- [x] **SEED-02**: Top 10 most-used concepts have full articles (all sections fleshed out, not just stubs): hexagonal architecture, NestJS guards, TypeORM repository pattern, Apigee API gateway, GCP Pub/Sub, JWT authentication, RBAC/permissions, NestJS interceptors, TypeORM migrations, session guard pattern
- [x] **SEED-03**: All stub and full articles wikilinked — concept articles reference related concepts; no orphan nodes in the graph

### LRNG — Learning Resources

- [x] **LRNG-01**: Domain reading queue documented per domain: coding patterns, system design, GCP/infra, DevOps, observability, communication — with books in priority order (one active per domain at a time)
- [x] **LRNG-02**: Podcast and video recommendations documented per domain: top 3 per domain, linked to resources notes in `40-resources/`
- [x] **LRNG-03**: Homework log created in Obsidian — dedicated section for assigned practice tasks, tracked with Tasks plugin (`[ ]` pending, `[/]` in-progress, `[x]` done)
- [x] **LRNG-04**: Resources Obsidian notes created for all initial book recommendations (metadata: title, author, domain, why relevant, link to concept articles that surfaced it)

### PRAC — Deliberate Practice

- [x] **PRAC-01**: Ticket pre-mortem habit established — before coding any non-trivial ticket: write business context, name 3 likely failure points, name the design pattern; stored in ticket reflection note
- [x] **PRAC-02**: PR rewrite drill — once per sprint, rewrite a merged PR from scratch (30 min), compare to original, capture diff observations in a reflection note
- [x] **PRAC-03**: Naked system design exercise — every two weeks, draw a cashea-backend subsystem from memory in Excalidraw (45 min), compare to code, document mismatches as new concept stubs or learning-gap tags
- [x] **PRAC-04**: One-concept deepening — 20 min weekly, pick one concept encountered but not fully understood, write or expand the full concept article
- [x] **PRAC-05**: Assumption logging — for any ambiguous ticket, write 2-5 explicit assumptions before implementation ("I'm assuming X because Y. If wrong: [consequence]") stored in ticket reflection

### SKILL — Skills & Tooling

- [ ] **SKILL-01**: `deslop` Claude Code skill created — reviews diff against main and removes AI-generated slop (extra comments, defensive checks, `any` casts, deep nesting) without changing behavior
- [ ] **SKILL-02**: `review-pr` Claude Code skill created — reviews open PR before team sees it, catches architecture issues, naming inconsistencies, missing tests, security concerns
- [ ] **SKILL-03**: Weekly skill retrospective — standing question in weekly review: "What repeated this week that should become a skill or automation?"

## Out of Scope

| Feature | Reason |
|---------|--------|
| Anki/SRS flashcards | Works for facts, not design judgment — not worth building. Weekly review handles spaced re-encounter |
| Obsidian Sync ($8/mo) | Git vault repo solves this for free |
| AI plugins in Obsidian | Claude via MCP is the AI layer — no separate plugin needed |
| Notion-Obsidian live sync | Notion = team/sprint context; Obsidian = personal knowledge. Link between them, never replicate |
| Separate practice project | cashea-backend work IS the practice. Synthetic side projects split focus |
| Generic reading lists | Resources must be embedded in concept articles at the moment of felt need |
| GCP Professional Cloud Architect cert | Too broad without dedicated infra ownership. ACE exam first |
