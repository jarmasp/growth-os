Title: `# Tag Taxonomy`

Description: Reference document for the Cashea knowledge vault tag system. Note that tags in YAML frontmatter are written WITHOUT the `#` prefix, and Dataview queries use `econtains(file.etags, "#tag-name")` for filtering.

Include three tables:

**Type Tags table** (what kind of note):
| Tag | Used In | Purpose |
| `concept` | 10-concepts/ | Permanent knowledge article |
| `ticket` | 20-tickets/ | Reflection tied to a ticket |
| `weekly` | 30-weekly/ | Weekly review |
| `resource` | 40-resources/ | Book/article/video metadata |
| `moc` | 50-mocs/ | Map of Content navigation index |

**Domain Tags table** (technical domain, a note can have multiple):
| Tag | Domain | Examples |
| `backend` | NestJS, TypeScript, TypeORM, hexagonal | Guards, interceptors, repositories |
| `database` | SQL, TypeORM, migrations, relations | Foreign keys, transactions |
| `infra` | GCP, Docker, Cloud Run, Pub/Sub | Secret Manager, Firestore, BigQuery |
| `system-design` | Architecture patterns, scaling | CQRS, event-driven, microservices |
| `observability` | Logging, tracing, monitoring | Datadog, Sentry, Pino |
| `security` | Auth, guards, JWT, RBAC | Session guards, permissions |
| `api` | REST, API gateway, Apigee | Proxy configs, rate limiting |
| `testing` | Unit tests, integration, e2e | Jest, mocking |
| `devops` | CI/CD, npm scripts, deployment | Pipelines, environment config |
| `communication` | PRs, code review, technical writing | ADRs, commit messages |

**Status Tags table** (lifecycle/gap signal):
| Tag | Meaning | Used By |
| `to-read` | Resource queued but not consumed | 40-resources/ |
| `in-progress` | Currently being read or worked on | 40-resources/ |
| `reviewed` | Consumed and takeaways captured | 40-resources/ |
| `learning-gap` | Knowledge feels weak, needs deepening | 10-concepts/ |
| `resolved` | Learning gap addressed | 10-concepts/ |

**Usage Rules section** (5 rules):
1. In YAML frontmatter: Write tags WITHOUT `#`: `tags: [concept, backend]`
2. In Dataview queries: Use `econtains(file.etags, "#backend")`
3. Inline tags: Write WITH `#` in note body
4. Multiple domains: A note can have multiple domain tags
5. Status tags: Add alongside type/domain tags

Frontmatter: `date: 2026-04-13`, `tags: [moc]`

Title: `# Workflow Rules`

Description: Standing rules for the Cashea knowledge vault workflow. Behavioral commitments, not enforced by templates.

**Rule 1: No Merge Without Reflection** (CAPT-03)
Before closing any branch or merging any PR: create a note in `Cashea/20-tickets/`, fill all sections (even one sentence per section counts). The ticket reflection is the receipt that you learned something. If tempted to skip: one sentence per section is better than nothing.

**Rule 2: Stub Before Session Ends** (CAPT-04)
When a new concept appears during a ticket: create a note in `Cashea/10-concepts/{domain}/`, fill at minimum title + one-sentence definition under "What It Is", add `#learning-gap` to tags if weak, link from ticket reflection's "Concepts Encountered" section. A stub is enough; full articles come later.

**Rule 3: Hard Weeks Use Survival Mode** (REFL-04)
Weekly reflection happens EVERY week. If brutal: use `weekly-review-survival.md` instead. Three questions, one sentence each. Still write the capability assertion. Skipping is worse than a one-paragraph survival review.
